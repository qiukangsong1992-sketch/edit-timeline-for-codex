# 架构与数据契约

## 入口

Codex 读取 `CODEX_HOME/hooks.json` 中的三个命令 Hook。PowerShell 启动器设置 `ELECTRON_RUN_AS_NODE=1`，用 VS Code 自带的运行时执行 `hook/bridge.cjs`。桥接器读取工作区接收端描述文件，向带随机令牌的 Windows 命名管道发送一条 JSON 消息并等待处理确认。描述文件只用于寻找管道；扩展不监听或轮询该目录。

`HookReceiver` 验证令牌及事件名称。`HookRecorder` 将输入按工作区、`session_id`、`turn_id` 分组；`tool_use_id` 用于工具前后配对与重复回调去重。三个事件共享一条提交队列。提示词事件不触发扫描。

## worker

`hook/scan-worker.cjs` 在独立 worker 中执行目录枚举、文件读取、哈希、gzip 压缩与解压、差异行数计算。补丁路径完整时只检查列出的路径，且校验真实路径仍在工作区内；其他工具每次重新枚举。正文 LRU 缓存上限 64 MiB，文件读取并发最多 4 个。元数据缓存比较设备、文件身份、大小、修改时间和变更时间；明确目标强制读取。

`PreToolUse` 保存前像并在 10 秒预算内返回。`PostToolUse` 比较前后像，写入内容寻址快照，再由宿主提交历史；提交后才给 Hook 回执。统计与树刷新随后执行。缺少前像、超时、二进制、文件过大或容量不足时，在记录中保存原因，不使用当前内容冒充旧内容。

## 历史和清理

历史元数据写入扩展的 VS Code 工作区状态；快照写入扩展独立的工作区存储。文件变化只保存哈希引用，回合内首次前像与最后后像生效。恢复操作先对被覆盖内容取快照，再写回文件，并生成一条可撤销的恢复记录。

删除、合并、清空和保留清理先完成历史写入，再释放旧引用。worker 从所有实际历史引用计数重建索引并分批清除孤立快照。置顶记录不参与自动清理；容量预留不足时优先删除最旧未置顶记录。清理与采集进入同一队列，避免物理删除正在提交的快照。

公开 API 提供历史、多个活动回合、按哈希读取快照及文件和回合恢复。当前 API 版本为 `1`。
